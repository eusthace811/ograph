7	# Incident investigation with ograph
8	
9	ograph keeps a knowledge graph of the service catalog, dependencies, business processes,
10	vendors, deployments, config changes, commits, alerts, incidents, log and metric anomalies, slow
11	or failed traces, exceptions, chat threads and news. Raw logs, metrics and traces stay in their own systems;
12	every event points back to its first raw record (`source_record`).
13	
14	## Quick start
15	
16	ograph needs `ogrep` on `PATH` (`ogrep --version`) to read the service catalog. Without it the
17	catalog harvest line says `DEGRADED: ogrep not runnable` and every fact about a service is
18	quarantined, so every answer comes back empty. Fix that first.
19	
20	```bash
21	ograph harvest    # commands search upward for .ograph/; the last line counts quarantined facts
22	```
23	
24	## Commands
25	
26	### Investigate
27	
28	```bash
29	ograph before INC-5377                 # default window 10m, 4 dependency hops
30	ograph before INC-5377 --window 45m    # widen when nothing shows up
31	ograph chains INC-5377                 # top 5 applications, each with its best chain
32	ograph chains INC-5377 --top 10
33	ograph chains INC-5377 --rank propagation   # second opinion: anomaly spread, not chain score
34	ograph blast ledger-db                 # name, alias or IRI of an application
35	ograph similar INC-5377 --top 3
36	ograph code INC-5377                   # lines, commits, files and past write-ups behind it (needs a code source)
37	ograph suspects INC-5377               # likely causes from dependencies and recent commits, no telemetry needed
38	ograph suspects checkout,payments --since 3d   # the same for failing applications
39	ograph news                            # all news; --since 24h, 7d counts back from now
40	```

44	```bash
45	ograph why INC-5377                    # every fact: graph, source, extractor, time, model provenance

50	```
